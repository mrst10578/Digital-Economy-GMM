## ۲. ممیزی نسخه‌ای HS واقعی در داده دوجانبه

[اجرای مستقل ممیزی نسخه‌ها](https://github.com/mrst10578/Digital-Economy-GMM/actions/runs/39020785743) تمام ۲۴۰ خانه آزمایشی **۸ کشور × ۱۵ سال (۲۰۰۸ تا ۲۰۲۲) × دو HS4** را با کدهای واقعی `classificationCode` منبع Comtrade و هفت فایل رسمی تطبیق داد:

- **۲۳۰ خانه** از داده دارای نسخه قابل شناسایی و معتبر HS هستند.
- **۱۰ خانه** به دلیل نبود رکورد واقعیِ مغولستان ۲۰۰۸–۲۰۱۲ فاقد داده و فاقد نسخه قابل استنتاج هستند؛ هرگز صفر نشده‌اند.
- در **هیچ‌کدام از ۱۱۵ جفت مقصد-سال دارای مشاهده**، نسخه HS میان دو گروه چهاررقمی مورد آزمون ناسازگار نبود.

| ویرایش واقعی منبع | تعداد خانه‌های مقصد–سال–heading معتبر |
|---|---:|
| H2 (۲۰۰۲) | ۲ |
| H3 (۲۰۰۷) | ۷۴ |
| H4 (۲۰۱۲) | ۷۶ |
| H5 (۲۰۱۷) | ۶۶ |
| H6 (۲۰۲۲) | ۱۲ |

**نتیجه روش‌شناختی مهم:** کشورها الزاماً در سال تغییر رسمی HS به همان نسخه گذر نمی‌کنند. مثلاً مولداوی در ۲۰۰۸ داده H2، سپس از ۲۰۰۹ H3 و از ۲۰۲۰ H5 دارد؛ ترینیداد و توباگو در داده ۲۰۰۸–۲۰۲۲ صرفاً H3 و H4 گزارش کرده است. استخراج آتی باید **نسخه گزارش‌شده هر مقصد-سال** را مبنا بگیرد، نه تقویم را.

## ۳. وضعیت API جامع‌تر و دسترسی رسمی

طبق [اشتراک رایگان UN Comtrade](https://uncomtrade.org/docs/subscriptions/)، حساب Basic Individual از **۵۰۰ درخواست API در روز** با حداکثر **۱۰۰ هزار رکورد در درخواست** پشتیبانی می‌کند؛ API بدون کلید، `preview` است و قابلیت جایگزینی جامع ندارد.

مسیر احتمالی جایگزین، جدول **«ICT goods: Bilateral trade by category - Annual» در مرکز داده UNCTAD** است. [پروب مستقل دسترسی بی‌کلید](../evidence/extended/UNCTAD_ICT_BILATERAL_PUBLIC_EXPORT_PREFLIGHT_2026-10-17.json) چهار مسیر احتمالی API رسمی را آزمایش کرد: دو پاسخ **HTTP 400** و دو پاسخ **HTTP 404**؛ در نتیجه **هیچ داده‌ای از این چهار مسیر دریافت نشد**. وجود جدول رسمی در وب‌سایت به معنی آزادبودن یک endpoint فاقد احراز هویت نیست.

### زیرساخت آماده برای API دارای کلید

[اسکریپت آزمون محافظت‌شده](../src/python/extended/preflight_free_comtrade_full_ict_hs6.py) و [گردش‌کار دستی ۶۵](https://github.com/mrst10578/Digital-Economy-GMM/actions/workflows/65-phase2-authenticated-full-comtrade-ict-hs6-preflight.yml) آماده شده‌اند:

- **فقط با فرمان دستی** و `secrets.COMTRADE_API_KEY` اجرا می‌شود؛ در نبود Secret هیچ API فراخوانی نمی‌کند.
- کلید را در URL، فایل یا لاگ ذخیره نمی‌کند و آن را با هدر اختصاصی می‌فرستد.
- اولین آزمون عمداً محدود به **۸ محصول ICT رسمی HS2017، کشور مقصد آذربایجان، سال ۲۰۱۷ و یک درخواست** است.
- داده‌های برگشتی از نظر نسخه HS، کد واقعی ۶رقمی، تجارت وارداتی، کلید یکتا، سقف ۱۰۰هزار رکورد و هش داده خام کنترل می‌شوند.
- اجرای آزمون کامل **هنوز انجام نشده** چون کلید حساب رسمی متصل نشده است. از نتایج پیش‌بینی‌شده نباید به‌عنوان خروجی واقعی استفاده کرد.

کلید از [My Comtrade → My API Portal](https://comtradeplus.un.org/MyComtrade/APIPortal) قابل دریافت است و بهتر است فقط به‌صورت GitHub Repository Secret قرار گیرد، نه در چت یا کد مخزن. چنانچه محدودیت‌ها اجازه دهند، پس از یک آزمون معتبر ابتدا برای جمع‌آوری پایلوت HS6 و سپس با برنامه تقسیم سهمیه برای ۴۷ کشور توسعه می‌دهیم.

## ۴. کار علمی باقی‌مانده و توقف‌های ضروری

۱. اعتبارسنجی نمونه‌ای اولین پاسخ API جامع رسمی و مطابقت آن با طبقه‌بندی کدهای رسمی.  
۲. تکمیل داده دوجانبه **۴۷ کشور × سال‌های ۲۰۰۵ تا ۲۰۲۲** با نسخه HS مشاهده‌شده برای هر مقصد-سال، مبدأهای مشمول و وضعیت missing.  
۳. تطبیق معناشناختی تغییرات کد و ادغام/تقسیم کدها بین نسخه‌ها، با حفظ خطای تبدیل؛ اشتراک ظاهری دو کد شش‌رقمی دلیل هم‌ارزی کالا نیست.  
۴. ساخت وزن‌های ثابت مبنای ۲۰۰۵–۲۰۰۷ تنها برای مجموعه دارای پوشش کافی، کنترل مجموع World و مبدأهای خارج از ۴۷ کشور، سپس محاسبه سنجه‌های توصیفی مواجهه خارجی.  
۵. مدل‌بندی تفکیکی FE و پویا همراه با طراحی اعتبارسنجی، سپس فقط در صورت شناسایی مستدل و دسترسی Stata واقعی، اجرای GMM.

**در این مرحله Stata اجرا نشده و لازم نیست. فاز اول استاد تغییری نکرده و هیچ تخمین جدیدی به‌عنوان یافته علّی معرفی نشده است.**
